## 1. 背景与问题

麦当劳官方 MCP 暴露 35 个工具，覆盖菜单、核价、门店、券、积分、抽奖、商城、团餐、派对等。
但用户真正的决策问题是：*「按我的预算、口味、热量目标，今天怎么买麦麦最划算，而且券真的能用？」*

实测发现四层信息断裂（证据见 SMOKE_TEST_REPORT）：

1. `productCode` 跨渠道不通用 → 无法直接比价。
2. 渠道费用与可用性差异大（同款差 ¥11.10）；得来速可能没有数据。
3. 券可用性受「门店 × 渠道 × 商品 × 时段」四维约束，实测 3 张券全部不可用。
4. 套餐换选 / 特调 / 营养约束会改变最优解。

现有公开作品多集中在「菜品推荐」与「自动下单流水线」，缺少**把渠道、资产、组合统一求解并给出可验证解释**的决策层。

## 2. 交付形态

**WorkBuddy Skill**。仓库根目录即技能本体，装进 `%USERPROFILE%\.workbuddy\skills\<name>\` 后由 WorkBuddy 加载。

| 组成 | 文件 | 职责 |
| --- | --- | --- |
| 决策协议 | `SKILL.md` | 触发条件、7 步流程、输出模板、常见坑、禁止事项 |
| 确定性计算 | `scripts/mcd-optimize.mjs` | 商品对齐、候选生成、排序、金额拆解、Markdown 报告（零依赖、不联网） |
| 工具契约 | `references/mcp-tools.md`、`references/pricing-and-coupons.md` | 35 个工具的真实入参/返回/错误码/降级策略 |
| 示例数据 | `references/fixtures/*.json` | 可直接喂脚本的脱敏输入 |
| 可选演示 | `demo/`（Next.js） | 可视化方案卡与调用链，非交付必需 |

设计原则：**MCP 给事实，脚本算账，Skill 管流程，WorkBuddy 说话。** 模型不参与价格算术。

## 3. 目标与非目标

### 目标
- G1：给定意图（预算 / 热量 / 必含商品 / 门店），输出 3 套**按实付升序**的方案。
- G2：方案价格**必须**来自 `calculate-price`；缺失时标注「⚠️ 预估」，不得伪装为实付。
- G3：券在**下单前**完成核销判定（`couponId` + `couponCode` 双参数试算），给出可用/不可用与业务码。
- G4：协议步骤、工具契约、错误码、示例全部可复核，证明「真的用了 MCP」。
- G5：默认 dry-run，写操作需用户显式确认。

### 非目标
- 不做自动支付 / 无人值守下单 / 多账号聚合。
- 不承诺积分兑换与抽奖（实测账号积分为 0，`resourceEligible=false`）。
- 不接入非官方数据源（不爬取、不接第三方比价平台）。
- 不把 demo 当交付物（可删除而不影响技能运行）。

## 5. 功能需求

### P0（技能本体，必须全绿）

| ID | 需求 | 载体 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 触发与前置检查 | `SKILL.md` | 列出触发词、缺门店/地址时先问 |
| F2 | 渠道探测 + 降级 | 协议步骤 1 | DT 失败（60047/60050）不阻塞，写入说明 |
| F3 | 跨渠道商品对齐 | 协议步骤 3 + `alignProducts` | 同款跨渠道被对齐，价差可算，单测覆盖 |
| F4 | 候选生成 + 硬约束 | 协议步骤 4 + `generateCandidates` | 预算/热量/必含过滤生效，单测覆盖 |
| F5 | 官方核价口径 | 协议步骤 5 | 明确「实付只认 `calculate-price.price`」，剔除 920174 |
| F6 | 券四维核销判定 | 协议步骤 6 | 双参数试算、60012/60010 语义、只对 top2~3 试算 |
| F7 | 输出模板与 dry-run | 协议步骤 7 | 方案表 + 券判定 + 说明 + dry-run 声明四件套齐全 |
| F8 | 踩坑清单与禁止事项 | `SKILL.md` | 至少覆盖 8 个实测坑 + 5 条禁止项 |
| F9 | 工具契约 | `references/mcp-tools.md` | 18 个已实测工具 + 错误码字典 + 未验证标注 |
| F10 | 脚本可复现 | `scripts/` | 零依赖、9 个单测通过、示例输入可跑出结果 |

### P1（时间允许）

| ID | 需求 | 价值 |
| --- | --- | --- |
| F11 | 特调层（`query-meal-detail` 的 `selectedKey/unselectedKey`） | 去酱/去冰/换选参与优化 |
| F12 | 资产体检（积分/券到期倒计时） | 主动提醒 |

## 6. 非功能需求

| 维度 | 要求 |

| 零依赖 | 技能本体不引入 npm 依赖，`node` 直接可跑 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 技能宿主差异（WorkBuddy 版本/描述触发不灵） | 用户说不触发 | description 写全触发词；README 给显式调用句式 |
| 得来速无数据 | 少一个渠道 | 协议内建降级，不作为失败 |
| 积分为 0 | 无法演示兑换 | 降级为体检，明确不承诺 |
| 券全不可用 | demo 无省钱高光 | 把「不可用判定」作为卖点，省额由跨渠道价差体现 |
| 核价限频 | 候选无法穷举 | 剪枝 + 32 次护栏 |
| 商品名不规范 | 对齐错误 | 别名表 + 最短匹配 + 宁缺勿错 |
| 时间不足 | 功能不全 | P0 优先，P1 只保特调层 |
